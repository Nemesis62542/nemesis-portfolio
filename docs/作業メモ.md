サイトの仕組みと、これまでの作業・残っている課題のまとめ。

## 1. サイトの仕組み（2026-09 以降）

```
content/projects/*.md   ← Projects の記事
content/blog/*.md       ← Blog の記事
        │  （ビルド時に data/content.ts が読み込む）
        ▼
    React のページ
        │  main に push すると GitHub Actions が自動でビルド
        ▼
  gh-pages ブランチ → https://nemesis62542.github.io/nemesis-portfolio/
```

- **Git リポジトリがそのままデータベース**。Markdown ファイルを編集して push すれば、それが公開される。
- 管理画面・ログイン・localStorage は廃止した（理由は「3. 作業ログ」を参照）。

### 記事の追加・編集

**Project を追加する**：`content/projects/` に `好きな名前.md` を作る。ファイル名がそのまま URL になる（例: `deep-voyager.md` → `#/projects/deep-voyager`）。

```markdown
---
title: 作品名
order: 6                # 大きいほど一覧の上に出る。新しい作品は今の最大値 + 1
featured: true          # Home の「代表作品」に出すなら true（出さないなら行ごと消す）
thumbnailUrl: assets/images/xxx.png
images:
  - assets/images/xxx.png
videos:
  - assets/videos/xxx.mp4
tags:
  - Unity
  - C#
links:
  - label: 作品ファイル
    url: https://...
---

ここから下が説明文（Markdown）。
```

**Blog を追加する**：`content/blog/` に `好きな名前.md` を作る。一覧は `date` の新しい順に並ぶ。

```markdown
---
title: 記事タイトル
date: 2026-09-23
excerpt: 一覧に出る短い紹介文
thumbnailUrl: assets/images/xxx.png   # 省略するとデフォルト画像
---

本文（Markdown）
```

- 画像・動画は今までどおり `public/assets/` に置いて、`assets/...` で参照する。
- 既存の記事のファイル名（`project-1.md` や `post-1756713110184.md` など）は、**シェア済みの URL が切れないように旧 ID のまま残している**。名前を変えると URL が変わるので注意。

### 編集中の見た目を確認する

```bash
npm run dev
```

起動したまま `.md` を保存すると、ブラウザに即反映される（旧管理画面のプレビューの代わり）。

### 公開する

- **main に push（PR をマージ）すれば自動で公開される**（`.github/workflows/deploy.yml`）。数分かかる。進み具合は GitHub の Actions タブで確認できる。
- 手動で公開したいときは、今までどおり `npm run build` → `npm run deploy` でも可。
- スマホからでも、GitHub の Web 画面で `.md` を直接編集してコミットすれば公開される。

## 2. 注意点

- **frontmatter（`---` で囲んだ部分）は YAML**。`:` や `#` を含む文字列は `"..."` で囲む。書式が壊れているとビルドが失敗する（＝壊れたまま公開されることはない）。
- 旧管理画面で編集していたブラウザには、古い `portfolio_projects` / `portfolio_posts` が localStorage に残っているが、もう読まれないので無害。気になれば開発者ツールで消してよい。

## 3. 作業ログ

### 2026-09-23

**OGP 画像が出ない問題を修正**
- `index.html` の `og:image` / `og:url` / `twitter:image` が旧リポジトリ名 `/game-developer-portfolio/` を指していて 404 だった。`/nemesis-portfolio/` に修正。
- ※ リポジトリ自体も GitHub 上では `nemesis-portfolio` に改名済み（旧 URL はリダイレクトで動いている）。

**コンテンツ管理を Markdown + Git 方式に移行**
- 旧方式の問題：
  - 管理画面での編集は **自分のブラウザの localStorage にしか保存されず**、訪問者には見えなかった。
  - 一度編集したブラウザでは、`data/*.ts` を直しても localStorage が優先されて表示が変わらなかった。
  - ログインはブラウザ内の JS だけで判定していたため、ソルトとハッシュが誰でも読める状態だった（静的サイトではサーバー側の認証ができないので、原理的に守れない）。
- 対応：
  - `data/projects.ts` / `data/posts.ts` の内容を `content/` 以下の Markdown に変換（未コミットだった「Deep Voyager」への改名なども含めて移行済み）。
  - `data/content.ts` で `import.meta.glob` を使い、ビルド時に Markdown を読み込むようにした。frontmatter は `yaml` パッケージで解析。
  - 削除：管理画面（`pages/Admin.tsx`）、ログイン（`pages/Login.tsx`、`contexts/AuthContext.tsx`、`components/ProtectedRoute.tsx`）、`components/MarkdownEditor.tsx`、`contexts/ProjectsContext.tsx` / `PostsContext.tsx`。
  - Home の「代表作品」はコード中の ID 指定から、frontmatter の `featured: true` に変更。
    - 並びは一覧と同じ `order` の大きい順になったので、「The Hungry Cat → マグロの惑星」の順に変わった。
  - GitHub Actions で main への push 時に自動デプロイするようにした。
- 認証が不要になったので、「ログインのセキュリティ」の問題も解消。

**その他の整理**
- 作品説明の「Cloude Code」→「Claude Code」。
- `vite.config.ts` から、使っていない Gemini API キーの設定を削除（AI Studio のテンプレートの名残）。`.env.local` は Git 管理外で、ビルドにもキーは含まれていないことを確認済み。
- README を AI Studio のテンプレートから、このサイト用の内容に書き換え。
